# 实施状态

**[English](implementation-status.md) | 简体中文**

本文概述已实现的工作流程及实际验证范围。交叉编译不等于在目标平台完成验收。

## 已实现的工作流程

程序包含八个可直接进入的阶段：扫描目录；设置按扩展名分类的规则；复制文件；校验副本；检查元数据；审核完全重复和视觉相似候选；备份到多个目标；创建加密 7z 归档。

- 扫描在后台运行，可取消，并跳过符号链接和特殊文件。程序会规范化父子目录选择，避免重复扫描相同文件。
- 分类和备份复制会保留相对路径、流式传输文件、比较 SHA-256，并避免覆盖已有目标。检查点可在重启后恢复部分复制计划和备份映射；恢复的任务会重新读取并校验文件。
- 元数据检查通过内置 ExifTool runtime 读取 GPS 和拍摄时间字段。状态区分缺失、不完整、无效、不支持和读取错误。用户可以确认一条警告，但不会因此改变字段状态。
- 重复审核可发现字节完全相同的文件，以及 JPEG、PNG、HEIC、HEIF 的图像候选。候选组可并排预览并排除。视频不参与感知哈希比较。
- 归档创建使用加密 7z Store 模式，支持分卷，并在提交前校验路径和 SHA-256。可选隔离还原校验会重新读取还原文件。恢复归档任务时必须重新输入密码，并从头重建。
- 界面支持美国英语和简体中文。首次启动默认英语；界面上始终可见的 **English** 和 **中文** 控件可即时切换语言，无需重启，并会记住选择。

## 构建和打包产物

各平台二进制文件具有固定的 target 路径，发布打包程序会将带版本号和架构标识的 ZIP 写入 `target/Releases/`。macOS ZIP 内含 `Photo Archive Manager.app` 应用包。确切文件名和重建命令见[发布说明](release.zh-CN.md)。

ZIP 打包器会排序条目、固定时间戳、包含校验和，并记录平台验收状态。这能让归档元数据保持稳定，但不保证不同工具链生成的二进制文件逐字节相同。

## 验证记录

- 已在 Apple Silicon 构建主机上使用原生窗口和文件选择器，并用临时目录检查扫描行为。arm64 应用包含 ExifTool/Perl runtime；构建时会校验 payload 摘要并重映射仓库和 Cargo 缓存路径。
- macOS Intel target 已在 Rosetta 下对应用和内嵌 ExifTool 做冒烟检查。这不能替代在 Intel 实机上测试。
- Windows x86_64 应用已交叉编译，并检查 GUI 子系统和非预期的 MinGW runtime DLL 导入；尚未在 Windows 上完成全流程运行。
- 此前锁定的 Rust 测试套件结果为 54 项通过、3 项忽略（两项需要外部 ExifTool 样本，一项为需显式运行的 2 GB 归档压力用例）。构建主机还记录了 2,000,000,001 字节归档用例和官方 7-Zip 互操作验证通过。
- HEIC/HEIF 预览解码已使用生成的 HEIC 样本验证；仍需真实相机和手机样本覆盖。

## 尚待验收

- 在 macOS arm64、macOS Intel 和 Windows x86_64 上完成断网、干净设备启动及全流程验收。
- 签名并公证 macOS 包；验证 Finder 启动、文件选择器、Dock 行为和 Gatekeeper 分发。
- 测试真实设备 HEIC/HEIF 样本及各平台路径、权限和可移动磁盘行为。
- 验证大型归档所需的临时空间。当前实现会先写入完整临时归档，再切分；峰值临时空间可能接近最终归档的两倍。隔离还原校验也需要存放还原副本的空间。
- 归档依赖内部的密码缓冲区不保证主动擦零；程序会清理自身持有的密码字符串。

剩余的人工检查见[验收清单](acceptance-checklist.zh-CN.md)，安全流程见[技术设计](technical-design.zh-CN.md)。
