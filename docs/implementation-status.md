# 实施状态与离线交付可行性

## 已落地

- Rust 原生窗口，底部可直接进入八个阶段。
- 阶段①可添加多个目录，递归列出常规文件、大小、mtime、扩展名，并显示错误样例。
- 新加入的父目录会吸收重复的子目录；路径规范化后去重。
- 扫描在后台线程运行，可取消；符号链接和特殊文件不会被递归跟随或当作照片计入。
- 阶段①结束后提供携带清单、不携带清单、停留、退出四个选择。
- 已在本机 macOS arm64 打开原生窗口与系统文件夹选择器；使用临时目录验证扫描计数和符号链接跳过。
- 阶段②按扩展名显示路由行，可为每种扩展名选最终文件夹，多种扩展名可合并到同一目录，也可添加自定义扩展名规则；未映射类型会显式保留并提示。
- 阶段③按默认清单过滤 `.DS_Store`、`._*`、`.Spotlight-V100`、`.Trashes`、`.fseventsd`、`Thumbs.db`、`desktop.ini`；界面可恢复包含。会预览未映射、目标已存在、目标重叠和重复路径；后台逐文件复制，目标存在时不覆盖，可重试未通过/未开始项。
- 阶段④可复核本会话复制结果，也可独立选择源/目标目录并按相对路径核对文件数、缺失/多余项、大小及 SHA-256。校验会重新读取目标内容；已通过手工界面验证同大小目标改写会报告不一致。
- 阶段⑤在 macOS arm64 构建中嵌入 ExifTool 13.60 与 Perl runtime；启动时验证有效载荷 SHA-256，在权限为 0700 的私有临时目录释放，退出后清理。批量读取所选整理目录或本次复制目标，直接传入 argv 并解析 JSON；不会调用 PATH 中的外部工具。
- 阶段⑤解析 GPS 纬度/经度及 QuickTime ISO 6709 坐标，校验坐标范围并保留有效的 `0,0`；按 EXIF 原始时间优先、视频 QuickTime 日期回退的顺序记录拍摄时间、精度、原始标签、时区状态和可选相机字段。没有把文件系统时间冒充拍摄时间；支持 `VALID`、`MISSING`、`PARTIAL`、`INVALID`、`UNSUPPORTED`、`READ_ERROR` 状态。
- 阶段⑥可独立选目录并重新扫描，逐文件重算 SHA-256、分组字节完全相同文件；可信且带时区的拍摄时间按用户阈值逐对比较，避免传递闭包，并跳过已知不同设备。JPEG/PNG 候选计算 64-bit pHash；界面显示路径、哈希、时间差、汉明距离，并允许将具体路径标记为本次排除。视频不参与 pHash，解码失败会显示原因。
- 阶段⑦支持每个本地来源目录配置多个目标目录，扫描并保留相对路径，阻止来源/目标重叠及嵌套，再复制并重新读取源和每个目标逐文件验证 SHA-256。目标结果独立呈现；共享目标产生重名冲突时不覆盖并逐项报错。
- 阶段⑧可独立选择目录、输出目录、归档名和十进制单卷上限；GUI 双次确认密码后，使用 Store、AES-256 和加密归档头创建 7z。临时归档先逐项对比输入清单并流式还原校验 SHA-256，再同步并用防覆盖硬链接提交。显式排除路径会从归档输入清单剔除。归档内保留唯一顶层来源文件夹及后代目录。
- 窗口底部可查看已打包的 ExifTool、sevenz-rust2、zeroize 声明和对应许可文本。完整的所有传递依赖许可审计仍未完成。
- 阶段①/③/④完成后提供四选项交接；“不携带”会清除下一阶段会用到的本次清单/结果。运行中切换会询问继续或在安全边界取消后切换；暂停与恢复尚未实现。
- `sevenz-rust2` 单卷归档已接入产品 UI：进程内密码、中文路径/密码、加密头、COPY 数据流和归档顶层目录通过本地流式 SHA-256 验证，并通过官方 7-Zip 26.05 arm64 `t`/`l` 互操作验证。
- 文件核心使用有界流式复制、源与临时目标 SHA-256、源扫描戳校验、mtime 保留，以及用同目录 hard-link 防覆盖提交。无法硬链接提交的文件系统会报错，不回退到可能覆盖的写法。

## 当前构建环境与限制

- 开发主机：macOS arm64；已安装 Rust 1.99.1，当前仅有 `aarch64-apple-darwin` target。
- 本机可编译源码，不等于干净 macOS 验收；目前也没有 Windows 构建或干净系统验收证据。
- 最新本机 Release 构建为约 20 MB 的 arm64 Mach-O，其中包含约 15 MB 的 ExifTool/Perl 有效载荷；`otool -L` 仅列出 macOS 系统框架与系统库。它尚未作为裸 GUI 文件在干净系统、Finder 或 Gatekeeper 流程中验收。
- macOS `.app` 是目录形式，不能代替严格单物理文件要求。裸 Mach-O GUI 的系统启动、文件选择器与分发行为尚未验证。
- 阶段②目前是逐扩展名路由，还没有来源级规则、同名冲突重命名或可用空间 dry run。阶段③目标已存在时只报错，不自动比较同名目标的 SHA-256。
- 阶段④的独立目录模式按相对路径匹配；Windows 大小写/UNC、macOS Unicode 规范化、权限/扩展属性、超大规模目录和外接盘掉线恢复尚未验收。
- 阶段⑥还没有缩略图预览、内嵌预览优先策略、完整 64-bit 格式覆盖或持久/导出的 Final Manifest；本次排除标记仅保存在会话内存。
- 阶段⑦没有暂停/断点恢复，也未处理大规模任务的恢复检查点；复制写入仍使用防覆盖提交，已经存在的目标会失败并需要人工处理。
- 阶段⑧已有产品 UI 和单卷加密 Store 校验；原生分卷仍未实现，不能满足超过 2,000,000,000 字节的单文件或数据集归档。恢复到临时隔离目录的可选校验尚未实现；目前执行的是内存流式解码、CRC 和逐文件 SHA-256 比较。
- 阶段⑥人工排除决定不会物理删除文件，但当前只是内存路径集合；没有持久的审计 Final Manifest，应用重启后决定丢失。
- ExifTool 有效载荷仅适用于本机 macOS arm64，测试通过不等于 Windows/macOS Intel 或干净系统验收。
- 本机 `cargo test` 最近一次结果：24 passed、0 failed、2 ignored（需外部样本的 ExifTool smoke tests）。覆盖扫描、垃圾过滤、元数据解析、内置 ExifTool 启动、重复 SHA/时间窗口边界、来源变更拒绝、流式复制、同大小目标改写识别、路径重叠保护、多目标备份读回校验、目标额外文件检查、加密 Store 7z manifest/SHA-256 验证、排除清单和单卷上限拒绝。
- `cargo build --release` 最近一次成功；产物 `target/release/photo-archive-manager` 是 macOS arm64 Mach-O，约 21 MB。`otool -L` 仅显示 Apple 系统框架与系统库。未在干净系统或 Windows/macOS Intel 上启动验收。
- 2026-11-02 使用从 [7-Zip 官方下载页](https://www.7-zip.org/download.html) 获取的 7-Zip 26.05 macOS arm64 临时验证单卷归档：交互输入中文密码后 `7zz t` 成功，`7zz l` 显示顶层 `Photos/`、子目录和中文文件名。验证程序位于临时目录，没有捆入产品；测试密码不写入产品进程参数。
- 生成的 `target/` 是开发产物，不是经过签名、公证或干净系统离线验收的发布包；不宣称 Windows 或最终单文件交付已达标。
